Running models locally

Where the models come from

Hugging Face is the repository. Three million public models as of August 2026, and the open-weight releases from Alibaba, Google, Meta, DeepSeek, Mistral and OpenAI all land there first.

What a listing holds

A model card, a license, and the weight files. Downloads and likes are on the page, so you can see what other people use.

Open weights, not open source

The weights are published; the license is the publisher’s own. Qwen is Apache 2.0, Llama and Gemma have custom terms. Read it before commercial use.

One model, several files

The same model is posted at full size and in smaller quantized copies. Which one you download is set by what your machine can hold.

What pulls and runs them

What it is What you use it for
Ollama A CLI and a local API, with its own registry that mirrors Hugging Face ollama pull, then one model in a terminal or behind localhost
LM Studio A desktop app over the same engines Browsing, downloading and trying models without a terminal
llama.cpp The C++ engine that runs these models on ordinary hardware What most of the above is running underneath
MLX Apple’s array framework, with mlx-lm for text The fastest path on Apple silicon
vLLM A batched inference server A queue of documents rather than a conversation

Ollama will also pull straight from a Hugging Face repository: ollama run hf.co/user/repo.

Two numbers

A model is a few billion numbers. At full size each takes two bytes. Quantizing rounds them to one of sixteen levels, with a scale factor kept for each small block — a quarter of the space, and a little accuracy. A billion parameters comes to a bit over half a gigabyte.

Memory decides whether it loads

All of it has to be in memory at once, with room left over for the conversation. 30 billion parameters is 17 GB; 671 billion is about 400 GB.

Bandwidth decides how fast it generates

Bandwidth is how many gigabytes a second the chip reads from its own memory. Each token — roughly a word — costs one full read of the weights in use.

tokens/sec ≤ bandwidth ÷ active bytes

Two machines

Unified memory is why these hold models a discrete card cannot: the GPU reads system RAM, so the capacity is the machine’s memory. An RTX 5090 has six times the Mac mini’s bandwidth but only 32 GB of memory.

Why a 30B model generates like a 3B one

Both of these are mixture-of-experts models: all the weights sit in memory, and each token reads a fraction of them.

  1. Memory holds the whole model — 17 GB for Qwen3-30B-A3B, about 400 GB for DeepSeek 671B.
  2. A router picks 8 experts out of 128 for each token.
  3. The read is 3.3B parameters, not 30B, so the ceiling is set by the active share.

A ceiling, not a measurement. Real throughput runs 60 to 80 percent of it, and falls as the context fills.

Security

Three risks

  1. Sending data to an LLM → risks of training on your data and data breach
  2. Letting an agent read unverified sources → risk of prompt injection
  3. If the agent can also reach data → risk of data exfiltration

Where a prompt goes

Every call leaves copies. Your agreement with the provider sets how long each one is kept.

Your app

The conversation history your own code keeps so the next turn has context.

Your gateway log

Who asked, which model, how many tokens — and, if you log bodies, the prompt itself.

The provider

Held for a period set by your agreement, and separately for abuse monitoring.

Subprocessors

The hosting and infrastructure vendors listed in the provider’s data processing agreement.

The answer to the first risk

For almost every business use, the answer is to sign a contract and send the data. A no-train, zero-retention Data Processing Agreement — plus a BAA for PHI — comes with the standard commercial API account.

Step What it adds Enough for
Opt out of training (a setting; API default) The provider will not train on it. A setting in the terms of service, revocable, and the data is still retained briefly Personal, non-sensitive work
+ Signed DPA (+ BAA for PHI) A contract: liability, breach notice, audit, subprocessor list Client data, regulated data, PHI
+ Enterprise agreement SLAs, support, indemnification, capacity, SSO Scale and operations, not stronger privacy

Beyond the contract

The DPA is a contractual guarantee, backed by liability. It is not a physical one: the data still travels to the provider. For more sensitive data, add a physical layer.

  1. Send less — the schema, and a few synthetic rows.
  2. De-identify — take the names out before the data reaches the context.
  3. Run a local model — the data never leaves your environment.

Steps 2 and 3 are the rest of this session.

What are prompt injections?

The mechanism

  • Hidden instructions embedded in data — emails, documents, web pages
  • The LLM reads the hidden text and follows the attacker’s instructions instead of the user’s
  • It cannot distinguish instructions from content; it is all text

The exposure

  • Any agent that reads untrusted content and has access to private data or tools
  • The attacker needs no credentials — only a way to get text in front of the LLM
  • OWASP ranks prompt injection as the #1 risk for LLM applications (2025)

Why agents are more exposed

A tool result re-enters the context as text, in the same stream as your question.

What you typed

“Summarize the overdue invoices.”

What a tool returned

A row, a web page, an email body — whatever was in the source, verbatim.

What the model sees

One sequence of tokens. There is no field marking which part you wrote.

EchoLeak: Zero-click data theft from Microsoft 365 Copilot

CVE-2025-32711 — June 2025

  1. The attacker sends the victim an email containing hidden instructions, invisible to a human reader.
  2. The victim asks Copilot to summarize their email. Copilot reads the hidden instructions.
  3. Following them, Copilot embeds confidential data in a URL in its response.
  4. The victim’s browser requests that URL, sending the data to the attacker’s server.
  5. The attacker reads the data out of the URL. Zero clicks, and nothing visible to the victim.

Copilot reads untrusted content, has access to private data, and can render URLs. All three in one LLM.

Three legs for data exfiltration

All three of these must be present for prompt injections to cause data exfiltration.

1. Private data

Secrets worth stealing — client records, financials, your inbox

2. Untrusted content

Attacker-controllable text — web pages, emails, uploaded files

3. An outbound channel

A way to send data out — web fetch, send email, write to a shared place

What follows from this

The leg you control

You cannot stop a model from reading instructions in its input, and you cannot always choose what a tool returns.

You decide how much of your data is in the context.

The other two

Untrusted content and the outbound channel are closed with containers and egress rules, when we build agents.

A local model does not close them: the machine still has a network.

De-identifying tables

Four kinds of field

Kind Examples What you do with it
Direct identifiers Name, SSN, account number, email, phone Suppress. Each one names a person on its own
Quasi-identifiers ZIP, birth date, sex, job title, dates of service Generalize. Identifying in combination, not alone
Sensitive attributes Diagnosis, salary, balance, the text of a complaint Keep. What you are protecting, and usually what the model needs
Everything else Product code, region, quantity Keep. Carries nobody’s identity

The HIPAA safe harbor

Eighteen identifiers come out, in nine groups. Remove all of them, and have no actual knowledge that what remains could identify someone, and the data is no longer PHI — no business associate agreement required.

Group What comes out
Names The individual’s, and those of relatives, employers, and household members
Geography Everything below the state, except the first three ZIP digits where that area holds more than 20,000 people
Dates Every element but the year. Ages above 89 become “90 or older”
Contact Telephone, fax, email
Numbers SSN, medical record, health plan, account, certificate, license
Device and vehicle Serial numbers, VINs, license plates
Online URLs, IP addresses
Biometric and images Finger and voice prints, full-face photographs
Catch-all Any other unique identifying number, characteristic, or code

Two HIPAA routes, and two GDPR terms

HIPAA

  • Safe harbor — remove the eighteen. Mechanical and auditable, and it discards data you may need
  • Expert determination — a qualified statistician certifies that the risk of re-identification is very small, and documents the method. Keeps more of the data

GDPR

  • Anonymized data falls outside the Regulation
  • Pseudonymized data is still personal data and still in scope. Replacing a name with a token does not make the data anonymous, because you hold the mapping

45 CFR 164.514(b)(1) and (b)(2); GDPR Article 4(5) and Recital 26.

The techniques

What it does What survives
Suppress Drop the field Nothing of it
Mask Keep the shape, drop the content: XXX-XX-4312 The format
Pseudonymize One stable surrogate key per person Joins, and counts per person
Generalize 34 → 30–39; 77005 → 770; a date → its month The distribution, at lower resolution
Perturb Add noise to amounts and dates Totals and trends, not single rows
Aggregate Group totals, with a minimum cell size Comparisons between groups
Synthesize Rows with the same schema and distributions The distributions, no real person’s data
Schema only Column names and types, no rows Enough to write a query

No model is involved

Every row in that table is arithmetic or a lookup. It runs on your machine, in code you can read.

df["customer_id"] = df["customer"].map(surrogate)   # from your own table
df["zip3"]        = df["zip"].str[:3]
df["month"]       = df["order_date"].dt.to_period("M")
df = df.drop(columns=["customer", "email", "phone", "zip", "order_date"])

df.groupby(["zip3", "month"]).size().min()          # the smallest group

pandas for the transforms, Faker for synthetic values, and ARX or sdcMicro when you need a certified k-anonymity report.

Three properties of doing it in code

  1. Deterministic — the same row always produces the same output, so you can write a test for it.
  2. Auditable — the rule for each column is a line of code you can show a regulator.
  3. Local — nothing is sent anywhere to decide what to remove, and the removal happens before anything leaves.

Re-identification

Massachusetts, 1997

The state released hospital discharge records for state employees with names and addresses removed. Latanya Sweeney bought the Cambridge voter roll for $20, matched on ZIP, birth date and sex, and found the governor’s records.

Netflix, 2008

Netflix released 100 million ratings from 480,000 subscribers, user IDs replaced by numbers. Narayanan and Shmatikov matched them against public IMDb reviews and named individual subscribers.

ZIP, birth date and sex identify 87 percent of the US population uniquely (Sweeney, 2000). The direct identifiers were gone in both of these cases.

A test you can run

Group the rows by the quasi-identifiers you are about to send. Count each group.

  • k-anonymity — no group smaller than k, so every record looks like at least k−1 others. Where a group is too small, generalize further or drop it
  • l-diversity — within a group, the sensitive attribute has to vary. If five records match on ZIP and month and all carry the same diagnosis, the diagnosis is known for all five

Pseudonymize out, re-identify in

Your code

Replaces each person with a surrogate key. The mapping table stays in your database.

The model

Sees CUSTOMER_0417 and the figures. Reasons over them, writes, returns.

Your code again

Reads the mapping back and puts the names in before anyone sees the output.

The model never holds the mapping, so nothing it emits — including anything an injected instruction makes it emit — carries a name.

Where it has to happen

In code, before the call

A system prompt telling the model to ignore the names does nothing about the names you sent.

Before your own log

The gateway logs prompts and completions. That log is a second copy of whatever you sent.

Not by the model doing the work

A model asked to redact a document has already read it.

De-identifying text

A table and a notes field

A table

The identifiers are in named columns. You decide once per column, and the decision holds for every row.

Free text

A notes field, an email body, a scanned PDF. The name is in the middle of a sentence, and so are the place, the quantity and the date.

Why this job needs the local model

The reason

A scrubber has to read the raw text. Sending it to a hosted model to decide what to remove sends the unscrubbed text.

The weights sit on your disk, so the unscrubbed document stays on your machine.

The size

Span tagging: find the name, return a label. The open models used for this run 4B to 12B parameters, under 7 GB on disk at 4-bit.

Choose by the recall you measure on your own sample.

Three tools, in order

Regex

SSNs, account numbers, phone numbers, emails — anything with a format you can write down. Exact and free, and it finds every string matching the pattern you wrote.

A named-entity scrubber

Microsoft Presidio, spaCy. A purpose-built NER model, not a general LLM: it tags people, places, organizations and dates, and hands back spans to replace.

A local LLM

The last pass, over what the first two left. It reads the sentence, so it catches the identifier that is identifying only in context.

The first two passes are deterministic and testable, so they run before the LLM.

Why the LLM goes last

It is not deterministic

The same paragraph twice can come back scrubbed two different ways. You cannot write a test that keeps passing.

It has no recall guarantee

Regex finds every string matching the pattern. An LLM finds most of them, and you do not know which it missed.

It can invent

Asked to replace a name, it may also rewrite the clause around it. Check that the rest of the text is unchanged.

Measuring the scrubber

No scrubber catches everything, so measure how much it misses.

  1. Take a sample of documents and mark the identifiers by hand.
  2. Run the pipeline over the same sample.
  3. Count what it missed and what it removed that it should have kept.
  4. Write both numbers down, with the date and the model, next to the decision to accept them.

Recall is the number an auditor asks for.

What de-identification does not do

It does not replace the contract

Your DPA and your vendor-oversight obligations apply to any vendor you use, whatever you send them.

It does not cover the agent’s tools

If a tool reaches the raw table, what you scrubbed out of the prompt is back in the context.

It is not free

A generalized ZIP cannot be geocoded; a perturbed amount cannot be reconciled. Decide what the answer needs first.
